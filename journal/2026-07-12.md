### S3 endpoint investigation — final findings (22:00–22:15 CST)

Deeper investigation revealed both S3 endpoints have protocol issues:

| Endpoint | curl response | rclone result | boto3 (remote) |
|----------|---------------|---------------|-----------------|
| `nm.aihuanxin.cn` | HTML homepage (Huanxin community website, nginx reverse proxy) | 504 Gateway Timeout after 10 retries | ListBuckets 500, ListObjects on `quantum-qwen25-coder-main` 404 |
| `iner.aihuanxin.cn` | HTML homepage (same Huanxin community site) | 200 but XML parse error (`attribute name without = in element`) | Not reachable from remote (HTTP 000) |

**Root cause:** Both endpoints are reverse-proxied by nginx to serve the Huanxin
community website at the root path. The S3 API is NOT at the root — it's likely
at a path prefix or different subdomain that the rclone config doesn't capture.
The `ai3_nm_s3_env.sh` script uses the same endpoint URL, so it would have the
same issue (but it runs rclone on the remote, which is missing).

**Path-style addressing attempt:** Tried boto3 with
`s3={"addressing_style": "path"}` on the `jtdlp-...` bucket — result not captured
(daemon transport too slow, background task output capture failed).

**Transport degradation:** The Huanxin daemon transport became extremely slow
(>60s per command) during this session, causing all `ai_shell.sh` calls to be
auto-backgrounded. Background task output capture is broken for daemon transport
(only captures the initial `[huanxin_shell:AI] Using daemon transport.` stderr
