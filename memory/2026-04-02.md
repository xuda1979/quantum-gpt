## Adaptive temperature escalation for GRPO deadlock recovery

### Problem diagnosed
Every GRPO smoke on ai2 since `smoke1` has ended with `low_reward_signal` skips.
Root cause: with `--group-size 4` and OmniCoder-9B still weak on quantum tasks,
all 4 sampled completions score similarly (all fail tests → near-zero reward,
small reward std → below `--min-reward-std 0.02`). No gradient signal → no update.

### Solution: AdaptiveTemperatureState
Implemented TDD-first in `training/grpo_utils.py`:
- `AdaptiveTemperatureState` dataclass tracks `consecutive_low_signal_skips`
- `current_temp()` = `min(base * (1 + step_size * consecutive_skips), max_temp)`
- `record_skip(reason)` — only increments for `low_reward_signal` (not other reasons)
- `record_update()` — resets counter after any successful gradient update
- `to_dict()` / `from_dict()` for `run_config.json` persistence

### Wiring in `training/grpo_trainer.py`
- New CLI args:
  - `--adaptive-temp-step` (default 0.15) — per-skip temperature escalation factor
  - `--adaptive-temp-max` (default 1.4) — temperature ceiling
- `generate_group()` now accepts an explicit `temperature` kwarg; receives `adaptive_temp.current_temp()`
- `record_skip(reason)` called at each of three skip paths
- `record_update()` called after each successful gradient step
- State replayed from `--resume-from` JSONL (warm-restart compatible)
- `run_config.json` now includes `adaptive_temp_step`, `adaptive_temp_max`, `adaptive_temp_state`

### Validation

### Expected impact
With `--adaptive-temp-step 0.15 --adaptive-temp-max 1.4`:
- After 1 consecutive `low_reward_signal` skip: temp → 0.8 × 1.15 = 0.92
- After 2 skips: temp → 0.8 × 1.30 = 1.04
- After 3 skips: temp → 0.8 × 1.45 → capped at 1.4
- Higher temperature → more diverse completions → higher chance ≥1 correct → reward std > threshold → actual gradient update

### User guidance integrated
User shared best-practice checklist for training reasoning models (GRPO/RL):
- Start simple (rule rewards + GRPO), validate pipeline before complexity
- Data quality > quantity; multi-difficulty coverage
- Progressive training: small SFT → RL → fine-tune; curriculum learning; checkpoints
- Monitor KL divergence, reward distribution, generation quality; set anomaly alerts
- Analyze failure modes; build error case library; targeted improvements
- Resource planning: RL is compute-heavy; allocate sampling vs. training budget carefully

These principles reinforce the current iteration direction:
- We are using curriculum sampling (TaskCurriculum)
- Adaptive temperature directly addresses reward distribution monitoring
- `--reward-brevity-weight` > 0 is available as a simple rule reward that adds signal even on all-failure groups
