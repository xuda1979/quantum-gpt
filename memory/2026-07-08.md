### Lightweight run-lineage + run-comparison tooling (W&B-free)
User asked whether the project uses W&B Artifacts + HF Datasets revision.
Answer: **no**. W&B only appears in `docs/frontier_llm_rd_infrastructure_practices_2026-05-26.md`
as a reference; no `wandb` import anywhere in `training/` or `scripts/`.
HF Datasets `revision=` is not used either. The project's existing
versioning mechanisms are: per-run `run_config.json` + `metrics.json`,
per-dataset `manifest.json` with `source_sha256`, `scripts/delivery_registry.py`
+ `scripts/build_delivery_artifact.py` (sha256 tarballs), and S3 relay
(`scripts/ai*_sync_*_s3.sh`) for air-gapped NPU transfer.

Built the lightweight, air-gapped alternative to a W&B runs table:
- `scripts/run_lineage.py` — stitches `run_config.json` + `metrics.json` +
  dataset `manifest.json` + linked `eval-*.json`/`scorecard.json` into a
  single self-describing `lineage.json` per run. Captures run identity,
  model/adapter provenance, dataset manifest, hyperparameters, final
  metrics, linked eval pass@1, and artifact sha256 hashes. Supports
  `build --run-dir X --write` and `scan outputs/` (batch).
- `scripts/compare_runs.py` — renders a compact table (or `--json`) of
  multiple runs from their `lineage.json` (or raw `run_config.json` if
  lineage not yet built). Columns: run, env, dataset, hp, metrics,
  eval@1, adapter.

Regression tests added: `tests/test_run_lineage.py` (5 tests, all
passing). Covers lineage extraction from a synthetic run dir, missing
metrics handling, compare_runs table + JSON output, and scan batch mode.

Verification:
- `python3 -m pytest tests/test_run_lineage.py` → 5 passed
- `python3 scripts/compare_runs.py --dir outputs/` → renders all 61 runs
- `python3 scripts/run_lineage.py build --run-dir outputs/codefirst-...`

### Lightweight dataset versioning + diff (DVC-free, the best-fit solution)
User asked about MLflow + DVC. Decision: **neither** — both add
operational overhead that doesn't fit our air-gapped NPU + S3-relay
workflow. Instead built the two missing DVC-equivalent pieces on top of
the existing manifest.json convention:

- `scripts/dataset_version.py` — content-addressed dataset registry.
  `snapshot <dir>` hashes every file + computes per-row sha256 for JSONL
  files, extracts manifest fields, writes a snapshot to
  `artifacts/dataset-registry/<dataset>@<ts>-<hash>.json`, and updates
  `artifacts/dataset-registry/index.json`. Supports `snapshot --all
  <root>`, `list`, `history <dataset>`, `lookup <path>`.
- `scripts/dataset_diff.py` — row-level dataset diff. Compares two
  snapshots (or two live dirs via `--dir A B`, or two registered versions
  via `--dataset X --versions 1,0`) and reports: manifest field
  changes (added/removed/changed), per-file changes (added/removed/
  modified with byte delta), and for JSONL files a positional row-level
  diff (unchanged/changed/added/removed row counts + indices).

Wired the dataset registry into `run_lineage.py`: a run's `lineage.json`
now includes `dataset.registered_version` with the content_hash +
snapshot_file of the registered dataset version, so every run points to
an immutable, content-addressed dataset version. This closes the loop:
run → dataset version → exact rows → reproducible.

Regression tests added: `tests/test_dataset_version.py` (8 tests, all
passing). Covers snapshot content hashing + row hashes, index updates +
dedup, list/history CLI, diff of added rows + manifest changes, diff of
changed rows, CLI --dir mode, and end-to-end lineage picks up registered
dataset version.

Snapshotted the real iter-1 + iter-2 datasets:
- `glm52_soft_distill_sft_100` (100 rows, content_hash 7b5765d8372b…)
- `glm52_soft_distill_sft_iter2` (155 rows, content_hash 3270c77e4588…)

### Complete lightweight MLOps stack (no external services)
The project now has the full experiment-tracking + dataset-versioning
stack, all as plain JSON files in Git/S3:

| Concern | W&B/MLflow/DVC equivalent | Our tool |
|---|---|---|
| Run config + metrics + system metadata | W&B Run | `run_config.json` + `metrics.json` (trainer-written) + `scripts/run_lineage.py` (stitched) |
| Run comparison table | W&B Runs table | `scripts/compare_runs.py` |
| Dataset versioning | DVC `import`/`add` + remote storage | `scripts/dataset_version.py` + `artifacts/dataset-registry/` |
| Dataset diff | `dvc diff` | `scripts/dataset_diff.py` |
| Model/adapter artifact registry | W&B Artifacts | `scripts/delivery_registry.py` + `artifacts/model-registry/` |
| Eval results + gap analysis | W&B Tables / custom | `evals/subsystem/{analyzer,dataset_gap,reporter}.py` |
| Lineage (run ↔ dataset ↔ eval) | W&B Artifact graph | `lineage.json` (run → dataset.registered_version → content_hash) |
| Air-gapped transfer | (not supported) | `scripts/ai*_sync_*_s3.sh` |
