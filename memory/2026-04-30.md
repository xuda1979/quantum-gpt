## Full Local Qwen3.6 RAG Test

- User asked to test the local version fully.
- Real local installer run downloaded `Qwen3.6-27B-Q4_K_M.gguf` (`15.65 GiB`) and installed `llama.cpp` via Homebrew.
- Real full doc fetch with an uncapped crawl was stopped after it spent more than 10 minutes inside Qiskit alone; fixed the installer default to a bounded all-source crawl and added `--exhaustive-docs` for uncapped crawling.
- Bounded all-source doc fetch completed:
  - `16` configured sources
  - `968` external doc files
  - `25` Arclight ISQ pages
  - final index: `13621` chunks, `996` sources, `50000` vectorizer features
- Full local CPU test result:
  - `Qwen3.6-27B-Q4_K_M.gguf` loads CPU-only with `0/65` layers offloaded, but direct 1-token generation timed out after `180s`; it is not practical on this 16 GB local machine.
  - Switched to allowed alternative `Qwen3.6-35B-A3B-UD-IQ2_XXS.gguf` (`10.01 GiB`, MoE active-size target), which loaded CPU-only with `0/41` layers offloaded.
  - Direct generation returned `OK.` in about `5.2s`.
  - RAG-backed Arclight ISQ query succeeded after retrieval fixes. Final answer used the Arclight install page and completed in about `81.7s` server time for `853` prompt tokens and `105` generated tokens.
- Fixes made during full test:
  - tolerate Homebrew `llama.cpp` install returning nonzero when `llama-server` is actually installed
  - avoid macOS Bash empty-array nounset failure in the doc-source loop
  - make doc crawl bounded by default (`80` pages/source), with `--exhaustive-docs` opt-in
  - force CPU-only server flags: `--device none --no-op-offload --no-kv-offload --cpu-moe --n-gpu-layers 0`
  - disable Qwen thinking in `llama-server`: `--reasoning off --reasoning-budget 0`
  - expose query timeout and no-cache controls in the wrapper
  - improve RAG reranking for explicit Arclight/ISQ/install queries
