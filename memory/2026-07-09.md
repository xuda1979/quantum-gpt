### Key finding: DR-GRPO was only half-wired
- The `doubly_robust_quantum_grpo` paper specifies TWO DR terms:
  (1) a DPO-style pairwise loss on in-group (chosen, rejected) pairs,
  and (2) a PPO-side variance correction `psi * E[(r-1)*A]`.
- Before this iteration, `training/grpo_trainer.py` only wired in
  term (1) via `compute_dr_pair_loss()`. Term (2)
  (`dr_variance_correction`) was defined and unit-tested in
  `dr_pair_loss.py` but NEVER CALLED by the live training loop.
- This is a real methodological gap: the "doubly robust" guarantee
  needs both terms. Running with only the DPO term is just
  "GRPO + DPO pair loss", not DR.

### Action: wired in the DR variance correction
- Added `compute_dr_variance_correction()` to `training/grpo_trainer.py`
  (parallel to `compute_dr_pair_loss()`). Reads `dr_psi_init` from the
  plugin config; returns a zero tensor when the plugin is absent or
  `psi == 0` (so base GRPO is unchanged).
- Wired it into the `total_loss` block right after the DPO pair loss:
  `total_loss += psi * E[(r-1)*A]`, with `r` the clipped PPO ratio
  and `A` the detached group-relative advantage.
- Added `dr_variance_correction_value` and `dr_psi` to each step
  record in `grpo_step_metrics.jsonl` for offline analysis.
- Added 4 new tests in `tests/test_doubly_robust_quantum_grpo.py`
  (no-op without methods, no-op with non-DR method, active with
  plugin, zero-psi fast path). **All 20 DR-GRPO tests pass; 30
  tests pass across DR + GRPO metrics suites.**
- Updated `research/papers/doubly_robust_quantum_grpo/paper.md`
  with a "Trainer integration status (2026-07-09)" subsection
