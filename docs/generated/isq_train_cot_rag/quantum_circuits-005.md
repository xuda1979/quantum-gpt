### Prompt

已知标准的SWAP门可以通过三个CNOT门来实现（例如：CNOT(0,1)、CNOT(1,0)、CNOT(0,1)）。但在超导等具有固定耦合架构的物理硬件中，两个相邻量子比特之间的CNOT门往往是“有向”的，即硬件可能仅原生支持以低位地址作为控制位的CNOT(0,1)，而直接执行反向的CNOT(1,0)会面临极高的错误率或根本无法实现。请问在不增加辅助量子比特的前提下，如何仅利用同向的CNOT(0,1)以及必要的单量子比特门来构造等效的SWAP门？请给出推导过程，并用isQ代码编写这种适配硬件单向限制的SWAP线路。

### Reference answer

这是一个非常贴近工程实际的深层问题。在真实的量子硬件（如超导量子平台）中，物理比特的拓扑连接往往是固定且有向的，这要求我们在编译量子程序时必须处理双量子比特门的方向性问题。我们可以通过巧妙运用单量子比特门来改变CNOT门的方向。

数学原理与推导过程如下：
标准的 SWAP 门可以分解为三个交叉方向的 CNOT 门：
SWAP = CNOT(0,1) · CNOT(1,0) · CNOT(0,1)

由于硬件限制无法执行 CNOT(1,0)，我们可以利用单量子比特的 Hadamard 门 (H门) 来翻转 CNOT 门的方向。在量子电路的恒等变换中，如果对控制位和目标位同时作用 H 门，就可以交换它们的位置，即满足以下恒等式：
CNOT(1,0) = (H ⊗ H) · CNOT(0,1) · (H ⊗ H)

我们将上述恒等式代入到标准 SWAP 门的分解公式中，即可得到纯单向 CNOT 的等价形式：
SWAP = CNOT(0,1) · [(H ⊗ H) · CNOT(0,1) · (H ⊗ H)] · CNOT(0,1)

经过展开，新的线路由 3 个同向的 CNOT(0,1) 和 4 对 H 门组成。由于在现代量子硬件中，单量子比特门（如 H 门）的执行时间和错误率远低于双量子比特门，这种用少数单比特门开销来规避反向 CNOT 的策略在量子编译器中极其常用且高效。

以下是符合要求的 isQ 代码实现：

```isq
import std;

qbit q[2];

// 硬件拓扑受限下的单向CNOT构建SWAP门
procedure main() {
    // 第1步：执行原生支持的正向 CNOT(0,1)
    CNOT(q[0], q[1]);
    
    // 第2步：通过 H 门等价变换，使得正向的 CNOT(0,1) 实现反向 CNOT(1,0) 的逻辑
    H(q[0]);
    H(q[1]);
    CNOT(q[0], q[1]);
    H(q[0]);
    H(q[1]);
    
    // 第3步：再次执行原生支持的正向 CNOT(0,1)
    CNOT(q[0], q[1]);
}
```

推导CNOT与CZ门等价关系的核心思路是利用Hadamard门（H）对泡利算符的共轭变换性质。首先，明确转换目标：验证在目标量子比特上前后各作用一次H门，即通过 $(I \otimes H)$ 算符，能否实现两个双量子比特门的转换。

在量子计算中，受控非门（CNOT）和受控相位门（CZ）是两个极为核心的双量子比特门。它们在量子电路中可以相互替代，这种等价关系建立在单量子比特Hadamard门的基础上。下面我将使用Dirac符号为你进行严谨的数学形式化推导。

首先，我们给出这两个双量子比特门的Dirac符号（投影算符）表示。设定第一个量子比特为控制比特，第二个为目标比特：
CNOT门的作用是当控制比特处于 $|1\rangle$ 态时，对目标比特作用 $X$ 门（泡利-X算符）：
$$ \text{CNOT} = |0\rangle\langle0| \otimes I + |1\rangle\langle1| \otimes X $$
CZ门的作用是当控制比特处于 $|1\rangle$ 态时，对目标比特作用 $Z$ 门（泡利-Z算符）：
$$ \text{CZ} = |0\rangle\langle0| \otimes I + |1\rangle\langle1| \otimes Z $$

Hadamard门有一个极为重要的代数性质，即它能够实现 $X$ 算符和 $Z$ 算符之间的基底变换（共轭变换）：
$$ H X H = Z $$
$$ H Z H = X $$
其中 Hadamard 门的定义为 $H = \frac{1}{\sqrt{2}}(|0\rangle\langle0| + |0\rangle\langle1| + |1\rangle\langle0| - |1\rangle\langle1|)$。

现在，我们来推导如何从CZ门构造出CNOT门。我们在CZ门的目标比特前后各作用一个Hadamard门，即计算 $(I \otimes H) \text{CZ} (I \otimes H)$：
$$ (I \otimes H) \text{CZ} (I \otimes H) = (I \otimes H) \left( |0\rangle\langle0| \otimes I + |1\rangle\langle1| \otimes Z \right) (I \otimes H) $$
根据张量积的分配律，我们可以将 $(I \otimes H)$ 拆解为 $|0\rangle\langle0| \otimes H + |1\rangle\langle1| \otimes H$ 并进行乘法运算：
$$ = \left( |0\rangle\langle0| \otimes HI + |1\rangle\langle1| \otimes HZ \right) (I \otimes H) $$
由于 $I$ 和 $H$ 都是针对目标比特的算符，结合律成立，进一步展开得：
$$ = |0\rangle\langle0| \otimes H I H + |1\rangle\langle1| \otimes H Z H $$
代入前文提到的 Hadamard 门共轭变换性质 $H I H = I$ 以及 $H Z H = X$，上式化简为：
$$ = |0\rangle\langle0| \otimes I + |1\rangle\langle1| \otimes X $$
观察可见，这正是CNOT门的定义。因此，我们得到了完整的等价转换公式：
$$ \text{CNOT} = (I \otimes H) \text{CZ} (I \otimes H) $$

同理，如果我们在CNOT门的目标量子比特前后分别作用 $H$ 门，也可以逆向推导得出：
$$ \text{CZ} = (I \otimes H) \text{CNOT} (I \otimes H) $$

扩展讨论：由于CZ门在数学形式上对于两个量子比特是完全对称的（$\text{CZ} = \text{SWAP} \cdot \text{CZ} \cdot \text{SWAP}$），这意味着利用上述等价关系，我们可以通过在控制比特和目标比特上同时包裹Hadamard门来实现CNOT门控制比特与目标比特的互换，即 $\text{CNOT}_{c,t} = (H \otimes H) \text{CNOT}_{t,c} (H \otimes H)$。这一数学等价关系在实际硬件架构设计中是不可或缺的，因为许多底层物理系统（如超导量子计算）天然更容易实现CZ门耦合，依赖此转换即可用底层CZ门完美映射高层的CNOT逻辑。

要用最直觉的方式理解“通过矩阵自定义门”，我们可以把量子计算想象成**玩乐高积木**。

通常情况下，我们写量子程序，就像是用厂家预先生产好的“标准乐高积木”（基础量子门，如X门、H门）来拼搭城堡。但是，如果你突然想要一个形状极其特殊的积木块，而包装盒里根本没有怎么办？

在这张设计图纸（矩阵）中：
1. **图纸的尺寸（矩阵的行列数）**决定了这块定制积木能插在几个量子比特上。比如，2x2的矩阵是一块作用在1个量子比特上的单孔积木；4x4的矩阵则是作用在2个量子比特上的双孔拼插积木。

3. 当然，量子世界有它的物理法则限制，你不能随便乱画图纸。你的设计必须满足“酉矩阵”的规则——这就好比你的积木不能无缘无故地凭空产生或消失质量，必须保证能量的完美守恒与平衡。

### Prompt

我理解了受控旋转门（如 $CR_z(\theta)$）的矩阵形式和基本逻辑，但在实际超导量子硬件中，通常只原生支持CNOT（或CZ）以及任意角度的单量子比特旋转门。请问如何将一个通用的受控旋转门分解为这些基础门序列？能否用isQ代码演示这一分解过程，并从酉矩阵等效性的角度证明其正确性？

### Reference answer

这是一个非常关键的进阶问题！在真实的量子硬件底层，由于物理实现的限制，我们往往无法直接执行任意角度的受控双量子比特门。因此，量子编译器的核心任务之一就是将这些高级门分解为硬件支持的基础门集（Native Gates）。

对于受控旋转门 $CR_z(\theta)$，我们可以使用两个 CNOT 门和两个单量子比特 $R_z$ 门来完美等效替换。具体的分解公式如下：
$$CR_z(\theta) = (I \otimes R_z(\theta/2)) \cdot CNOT \cdot (I \otimes R_z(-\theta/2)) \cdot CNOT$$

我们可以通过酉矩阵的代数性质来证明这个分解是正确的：
1. **当控制位为 $|0\rangle$ 时**：CNOT 门不会触发，相当于目标位上的恒等操作 $I$。此时目标量子比特经历的变换为：$R_z(-\theta/2) \cdot R_z(\theta/2) = I$。整体效果是对目标位无任何操作，这与 $CR_z(\theta)$ 控制位为 $|0\rangle$ 时的行为完全一致。
2. **当控制位为 $|1\rangle$ 时**：CNOT 门相当于对目标位施加 $X$ 门。目标量子比特经历的变换为：$X \cdot R_z(-\theta/2) \cdot X \cdot R_z(\theta/2)$。根据泡利矩阵的性质，$X$ 门与 $Z$ 门是反对易的，即 $X Z X = -Z$。带入旋转门定义可得 $X R_z(\phi) X = R_z(-\phi)$。所以上述序列等价于：$R_z(\theta/2) \cdot R_z(\theta/2) = R_z(\theta)$，这正好实现了受控位为 $|1\rangle$ 时对目标位旋转 $\theta$ 的要求。

下面是使用 isQ 语言实现该逻辑的代码。我们以 $\theta = \pi/2$ 为例，展示如何用基础门拼接出等效的受控旋转电路：

<isQ>
import std;

qbit q[2];

procedure main() {
    // 假设 q[0] 为控制位，q[1] 为目标位
    // 目标：实现 CRz(pi/2, q[0], q[1])
    
    // 第一步：目标位旋转 -pi/4
    Rz(-pi/4, q[1]);
    
    // 第二步：执行 CNOT 门
    CNOT(q[0], q[1]);
    
    // 第三步：目标位旋转 pi/4
    Rz(pi/4, q[1]);
    
    // 第四步：再次执行 CNOT 门
    CNOT(q[0], q[1]);
}
</isQ>

通过这种分解策略，我们不仅将抽象的受控旋转门转化为了硬件原生支持的指令集，而且仅使用了两个 CNOT 门。在实际的 NISQ（含噪中等规模量子）设备中，双量子比特门的错误率通常比单量子比特门高出一个数量级以上。因此，这种最少化双量子比特门数量的编译优化，对于维持深层量子算法的保真度至关重要。

### Reference answer

<think>
首先，厘清量子电路深度的基本定义，指出其本质是“关键路径上的最长串行门序列”，而非总门数在比特上的均摊。

其次，分析量子门并行执行的物理前提：只有作用在完全独立的量子比特上的操作才能同时执行。

接着，抓住量子计算的核心特征——量子纠缠。多量子比特门会打破量子比特的独立性，产生严格的因果依赖，这意味着纠缠后的后续操作必须按特定顺序串行执行。

最后推导结论：任何有意义的量子算法都包含固有的串行纠缠结构，这决定了电路的关键路径存在不可压缩的下限。单纯增加辅助比特（电路宽度）无法打破这种由纠缠决定的因果关联，从而彻底推翻了“增加比特数必然按比例稀释深度”的错误假设。
</think>

这种说法是非常典型的初学者陷阱，它完全错误地理解了量子电路深度、宽度以及量子门之间依赖关系的本质。

**陷阱分析：**
这个谬误源于将量子计算简单地类比于经典计算中的“ embarassingly parallel （易并行）”问题，认为只要增加计算节点（量子比特），所有操作就可以均匀分配并同时执行。它忽略了量子算法中普遍存在的量子纠缠带来的严格因果依赖，且误解了电路深度的基本定义。

**详细纠正：**
1. **电路深度的定义非“门数平均”**：电路的深度并非“总量子门数 ÷ 量子比特数”。深度是指电路中从输入到输出的所有路径中，包含最多的不可并行量子门的数量（即关键路径的长度）。如果两个门作用在同一组量子比特上，或者后一个门依赖前一个门的计算结果，它们就必须串行执行。
2. **纠缠带来的强依赖性限制了并行**：在大多数有意义的量子算法中，量子比特之间需要通过多量子比特门（如CNOT、CZ等）建立纠缠。一旦比特A和比特B发生纠缠，随后对比特A执行的单量子门操作，往往会深刻影响整个纠缠系统的状态演化。这种跨比特的纠缠使得后续很多看似只作用在单个比特上的门无法与其他门并行。
3. **增加宽度并不总是能减少深度**：虽然在某些特定情况下（如分解多控Toffoli门），增加辅助量子比特可以将部分串行操作转化为并行操作，但这存在严格的理论极限。对于许多复杂的量子算法（如量子傅里叶变换 QFT），其电路深度具有固有的复杂度下界。盲目增加量子比特不仅不能线性降低深度，反而会因为需要引入额外的 SWAP 操作（将物理上不相邻的比特移动到相邻位置）而大幅增加电路的深度和噪声。

以下是一段简单的 isQ 代码，演示了三个量子比特的 GHZ 态制备。通过观察代码可以直观发现，尽管只使用了很少的门，但由于后续的 CNOT 必须严格等待前一个 CNOT 完成才能在纠缠态之间传递信息，关键路径被拉长，深度根本无法通过“增加比特”来稀释。

```isQ
import std;

qbit q[3];

procedure main() {
    // 第1层：第一个Hadamard门
    H(q[0]);
    
    // 第2层：第一个CNOT门，依赖q[0]的状态
    CNOT(q[0], q[1]);
    
    // 第3层：第二个CNOT门，依赖q[1]刚刚改变的状态
    CNOT(q[1], q[2]);
    
    // 此时电路门总数为3，宽度为3。按错误观点，深度应为 3/3=1。
```

### Reference answer

这是一个非常深刻且直击物理实现底层的好问题。你十分敏锐地察觉到了高级量子编程语言中的语法糖与底层物理硬件原生指令集之间的差异。

将负控制转换为正控制（即底层硬件支持的操作）的核心逻辑非常简单且优美：只需要在控制比特作用目标量子门之前和之后，分别对该控制比特施加一个 X 门（泡利-X 门）即可。

从数学和状态演化的角度来看，X 门的作用是翻转量子态（即 |0〉 变成 |1〉，|1〉 变成 |0〉）。当我们在控制比特上先作用一个 X 门时，原本处于 |0〉 的控制量子态被翻转成了 |1〉，此时如果应用正控制逻辑的目标门，就恰好等效于在初始状态为 |0〉 时触发了该门。随后，我们再作用一个 X 门将控制比特的状态翻转回初始值，从而确保整个量子系统其他部分的相对相位和状态不被破坏。这也是所谓的“控制条件翻转”的标准电路构造方法。

下面我通过 isQ 代码来直观地展示这两种写法的等效性。假设我们有一个双量子比特系统，我们要在 q[0] 为 |0〉 时对 q[1] 执行 X 门。

import std;

qbit q[2];

    // 初始化状态假设

    // 方法一：使用 isQ 原生的负控制修饰符 nctrl
    // 这是一步到位的高级写法，可读性极高
    nctrl @[q[0]] X(q[1]);

    // 方法二：使用基础的正控制（ctrl）和 X 门进行等效替换
    // 这是编译器在底层实际展开的电路逻辑
    X(q[0]);             // 第一步：将 |0〉 翻转为 |1〉
    ctrl @[q[0]] X(q[1]); // 第二步：执行正控制非门（即标准的 CNOT 门）
    X(q[0]);             // 第三步：将控制比特的状态翻转回去以还原计算空间
}

在这段代码中，方法一和方法二在数学上完全等价，产生的量子态演化轨迹也是一致的。值得注意的是，虽然 nctrl 极大地提升了代码的简洁性和可维护性，但在物理硬件上执行时，它实际上引入了两个额外的 X 门操作。在复杂的量子算法（如多路复用电路或多控制 Toffoli 门的分解）中，如果大量嵌套使用负控制，会导致实际运行的电路深度显著增加。

因此，isQ 等高级语言提供 nctrl 的意义在于提高程序员的抽象层级，减少手动展开带来的错误风险。而底层编译器则负责将这些充满表达力的代码机械且准确地翻译成硬件能够理解的脉冲序列。在少数对电路深度极度敏感的优化场景中，高级程序员依然需要清楚这层隐藏的 X 门开销。

```isq
    H(ctrl[1]);

    // 例如，将AND的结果作为某种条件施加相位：
```

### Reference answer

<thinking>此问题涉及计算复杂性与热力学之间的深刻联系。学生已经明白量子门是可逆的，但不可逆经典操作在量子计算中不可避免（如Oracle）。为了在不耗散能量的情况下清除“垃圾信息”，必须使用Bennett计算 reversible computing 技巧：计算、保存结果到目标比特、反计算。这样辅助比特会自动恢复到初始状态，而无需进行引发热量耗散的热力学测量/重置操作。这里需要利用Toffoli门来实现AND逻辑，并用isQ代码展示这一过程。

代码设计：
1. 准备包含输入的比特和初始化为|0>的辅助比特（用于存储中间垃圾）以及目标比特（存储最终结果）。
2. 使用Toffoli门模拟AND。
3. 将结果通过CNOT转移到目标比特。
4. 逆向执行Toffoli门。
整个过程完全是幺正且可逆的，辅助比特恢复到|0>。
</thinking>
这是一个非常深刻且直击量子计算物理本质的问题。答案是：如果我们在量子电路中直接对辅助比特进行“测量并强制重置”来模拟经典计算的擦除过程，确实会触发Landauer原理，导致每擦除1比特信息产生至少 $k_B T \ln 2$ 的热量耗散，并且测量操作会破坏量子态的相干性。

为了解决这个矛盾，量子计算机采用了一种被称为**Bennett计算**的可逆计算技巧。其核心思想是：将所有不可逆的经典逻辑通过引入辅助比特（通常称为“垃圾比特”）转化为可逆的逻辑门（例如用Toffoli门代替AND门）。计算完成后，我们不直接测量和重置这些辅助比特，而是通过将计算过程逆向执行（反计算/Uncomputation），让这些辅助比特的量子态自然、确定性地退回到初始状态 $|0\rangle$。

这样，我们不仅在不产生任何热耗散的情况下“干净地”重置了辅助比特以供后续复用，同时还避免了因测量导致的波函数坍缩，完美维持了量子并行计算所需的相干性。

下面是使用isQ语言编写的示例代码，展示了如何可逆地计算“逻辑与(AND)”，并在保留计算结果的同时，不耗散能量地恢复辅助比特：

```isQ
import std;

const int N = 3;
qbit q[N];     // q[0], q[1] 为输入控制比特，q[2] 为辅助比特，初始态均设为特定值
qbit target;   // 用于保存最终 AND 结果的目标比特

procedure main() {
    // 假设初始输入为 |1>|1>|0>|0>
    X(q[0]);
    X(q[1]);

    // 第一步：正向计算。利用 Toffoli 门计算 q[0] AND q[1]，结果保存在辅助比特 q[2] 中。
    // 此时 q[2] 变为 |1>。此过程完全幺正可逆。
    Toffoli(q[0], q[1], q[2]);

    // 第二步：将结果转移到目标比特。由于 target 初始为 |0>，执行 CNOT 即可完成复制。
    CNOT(q[2], target);

    // 第三步：反计算。逆向执行刚才的计算过程。
    // 这会将辅助比特 q[2] 重新推回 |0>，从而在不进行任何破坏性测量的情况下“擦除”了垃圾信息。
    // 由于 q[0] 和 q[1] 状态未改变，逆 Toffoli 完美抵消了第一步的纠缠。
    inv Toffoli(q[0], q[1], q[2]);
}
```

通过上述机制，量子计算机在算法层面规避了Landauer原理带来的能耗下限，这也是理论物理学家认为量子计算在极端底层物理功耗上具有巨大潜力的原因之一。

设系统两比特初始态表示为密度矩阵 $\rho_{in}$。对控制量子比特 $q_c$ 进行投影测量，其对应的测量算符可分别定义为：
$$ M_0 = |0\rangle\langle0|_c \otimes I_t $$
$$ M_1 = |1\rangle\langle1|_c \otimes I_t $$
其中 $I_t$ 为作用在目标比特上的恒等算符。根据测量结果引发的经典条件反馈操作，该过程整体的量子通道 $\mathcal{E}$ 可写为：
$$ \mathcal{E}(\rho_{in}) = M_0 \rho_{in} M_0^\dagger + (I_c \otimes X_t) M_1 \rho_{in} M_1^\dagger (I_c \otimes X_t^\dagger) $$

进一步地，使用Dirac符号，若输入态为某个纯态 $|\psi_{in}\rangle = \alpha|00\rangle + \beta|01\rangle + \gamma|10\rangle + \delta|11\rangle$，经过上述过程后，量子态发生坍缩并可能产生受控翻转，演化轨迹将分解为以下两种情况：
1. 测量得到0（概率 $P(0) = |\alpha|^2 + |\beta|^2$）：目标比特不翻转，状态变为 $\frac{\alpha|00\rangle + \beta|01\rangle}{\sqrt{P(0)}}$。
2. 测量得到1（概率 $P(1) = |\gamma|^2 + |\delta|^2$）：目标比特执行X门翻转，状态变为 $\frac{\gamma|11\rangle + \delta|10\rangle}{\sqrt{P(1)}}$。

```isq
// 声明用于演示的全局量子比特

// 定义一个名为 conditional_flip 的过程
// 该过程封装了对控制比特的测量以及基于测量结果对目标比特的反馈操作
procedure conditional_flip(int c_idx, int t_idx) {
    // 对控制比特执行测量，结果存入经典变量 r
    int r = M(q[c_idx]);

    if (r == 1) {
        // 若测量结果为1，则对目标比特施加 X 门
        X(q[t_idx]);
    }
}

procedure main() {
    // 初始化量子态，制备叠加态和纠缠初态
    H(q[0]);
    H(q[1]);
    
    // 调用定义好的过程
    conditional_flip(0, 1);
}
```

这个观点是**完全错误**的。这是一个在初学者中非常常见的陷阱。

**错误说法剖析：**
初学者往往将“独立的量子态具有全局相位不可观测性”误推导为“在量子线路中全局相位门永远无用”。在纯粹的独立量子态中，全局相位 $e^{i\theta}$ 确实在计算测量概率 $|\psi|^2$ 时会被抵消。然而，量子计算并不是孤立态的简单演化，而是多量子比特之间的复杂干涉与纠缠过程。如果在程序中随意删除全局相位门，在特定的算法结构下会导致致命的干涉错误。

**深入纠正与原理解析：**
在 isQ 语言中，`GPhase(theta)` 的数学表示是 $e^{i\theta}I$。它的关键陷阱在于**受控操作**。

当我们单独使用 `GPhase(theta)` 时，它确实不会改变测量概率。但是，量子算法（如格罗弗算法的 Oracle、量子相位估计等）经常需要将包含相位的操作作为受控门来调用。在受控调用中，如果子操作包含全局相位，这个“全局”相位就会转化为控制比特与目标系统之间的**相对相位**。

具体来说，假设我们对一个包含 `GPhase(\pi)` 的子程序进行受控调用（控制比特为 $c$）。当控制比特 $c$ 处于 $|1\rangle$ 时，目标支路会获得 $e^{i\pi}$ 的相位；当 $c$ 处于 $|0\rangle$ 时，不获得该相位。这就导致整个系统在控制比特的计算基下产生了 $(-1)$ 的相对相位差。相对相位是绝对可观测的，它直接决定了后续量子干涉的结果。如果此时你认为“全局相位无用”而将其删除，就会抹除这个相对相位，导致干涉条件被破坏，算法完全失效。

此外，在 isQ 编译器对复杂量子门进行分解、或者使用 `inv` 求逆操作时，`GPhase` 经常作为代数等价转换的副产物出现。它是维持酉矩阵数学严谨性的基石。

以下是在 isQ 中演示该概念的结构示例代码：

```isq

qbit q[2];

// 包含全局相位的自定义操作
procedure my_oracle() {
    X(q[1]);
    GPhase(pi); // 这里的全局相位在受控调用时至关重要
    X(q[1]);
}

procedure main() {
    // 初始化为叠加态
    H(q[0]);
    H(q[1]);
    
    // 单独调用 my_oracle 时，GPhase 不影响概率分布
    my_oracle();
    
    // 假设在某种高级算法设计中，我们需要受控调用该 Oracle
    // 如果在此受控过程中 GPhase 被错误地忽略，
    // 那么控制比特 q[0] 将无法获得正确的相对相位反馈，干涉失效。
```

总结而言，`GPhase(theta)` 是维持量子操作代数完备性的重要工具。在编写和优化量子程序时，绝不能以“物理上不可观测”为由盲目剔除所有全局相位，尤其是在涉及受控逻辑和逆运算的复杂量子线路中。
