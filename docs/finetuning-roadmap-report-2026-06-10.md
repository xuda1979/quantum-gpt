# 量子大模型工作进展和计划

## 1. 基本思路与依据

量子计算是一个非常专业的垂直领域。我们的目标是研发具备量子计算代码编写、量子计算科学研究，又具备智能体软件开发能力的大模型。

我们这次不追求盲目扩大数据集。之前很多尝试证明，混入大量低质数据反而会破坏模型基础能力。我们的思路是以高质量样本进行精细微调，主要有以下几个依据：

*   **精简数据对齐（LIMA 机制）**：Meta AI 的研究（arXiv:2305.11206）表明，模型的绝大部分知识在预训练阶段就已具备，精调的核心是规范模型的输出格式。100 到 200 条高质量样本，在效果上往往优于大量带有噪声的数据。
*   **高质量演示样本（OpenAI 精调指南）**：OpenAI 最佳实践也指出，50 到 100 条格式完整、可编译、能通过单测的高质量样本，就能明显改善模型在特定 API 调用和纠错上的表现。
*   **大模型样本效率更高（Scaling Laws for Transfer）**：Kaplan 等人（arXiv:2001.08361）已指出大模型学习更快、样本效率显著更高。OpenAI 进一步在"预训练模型迁移到 Python 代码任务"上给出了定量公式（Hernandez et al., arXiv:2102.01293）：预训练等效贡献的数据量 $D_T = k \cdot (D_F)^{\alpha} \cdot N^{\beta}$，文本→代码场景拟合值 $\alpha \approx 0.18$，$\beta \approx 0.38$。反解可得，达到同等效果所需的微调数据量随参数量 $N$ 幂律下降：
    $$D_F \propto N^{-\beta/\alpha} \approx N^{-2.1}$$
    即模型参数量扩大 10 倍，所需微调数据量约降低两个数量级。我们选用 35B 级基座配合百条量级高质量样本，正是这条定律的直接应用。

## 3. 微调方案

我们将微调体系并行推进为两条训练线路：

### 3.1 Track A：多框架量子算法微调（算法 SFT）

*   **业务目标**：解决模型在 Qiskit、Cirq、PennyLane 等主流框架中，由于接口频繁更迭导致的 API 混淆和语法报错问题。
*   **高质量数据集**：
    *   基础数据：[data/curated/quantum_algorithm_coding_100_v1.jsonl](data/curated/quantum_algorithm_coding_100_v1.jsonl)（已精标注的 64 道高难度多框架量子考题）。
    *   蒸馏数据：[data/generated/quantum_distillation_teacher_responses_asi2_v1_high_quality_sft/train_chatml.jsonl](data/generated/quantum_distillation_teacher_responses_asi2_v1_high_quality_sft/train_chatml.jsonl)（利用强模型生成的蒸馏数据）。
    *   数据集规模：共 203 条量子高精度案例（训练集 183 条，验证集 20 条，按 9:1 切分，无重复重叠。见 [data/generated/quantum_distillation_teacher_responses_asi2_v1_high_quality_sft/manifest.json](data/generated/quantum_distillation_teacher_responses_asi2_v1_high_quality_sft/manifest.json)）。
*   **微调手段**：使用 LoRA 参数高效微调，锁定全 Linear 算子。在 MoE 架构（如 Qwen3.6-35B-A3B）上冻结混淆路由，运行 1 到 3 个 Epoch，保住基础通用指令能力，暂时不走强化学习。
*   **已有结果**：微调 Qwen 3.6 27B，在 20 条验证集上（大模型打分）：基座模型 9.6/20，微调后 15.5/20。

### 3.2 Track B：ISQ 量子编译语言思维链微调（ISQ-CoT SFT）

*   **业务目标**：让模型在面对复杂且容错率低的量子编译器（ISQ）开发时，学习通过思维链推理解决长链逻辑规划和语法纠错。
*   **数据整理**：
    *   源数据：[isq_train_cot.json](isq_train_cot.json)。
    *   数据集划分：使用 [scripts/prepare_isq_cot_sft_split.py](scripts/prepare_isq_cot_sft_split.py) 自主格式化并稳定切分出了 [data/generated/isq-cot-sft-80-20-v1](data/generated/isq-cot-sft-80-20-v1)（ChatML 思维链格式）。
    *   数据规模：**总计 5,611 条包含思维链的数据（训练集 4,488 条，验证集 1,123 条）**。
*   **计划安排**：本周完成。

### 3.3 主流微调方法对比（LoRA, QLoRA, DoRA）

| 微调方法 | 核心机制 | 可训练参数占比（典型） | 优点 | 缺点 | 适用场景 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **LoRA** | 在线性层旁注入低秩低维的并行矩阵 A 和 B。 | 0.1% ~ 1% | **推理无额外开销**：训练完后可将参数直接合并回模型权重。稳定性好。 | 需要微调确定 rank 和 alpha 等超参数。 | 主流指令微调、多框架量子代码微调首选。 |
| **QLoRA** | 双重重构：基座模型冻结为 4-bit 并使用双量化，仅通过 16-bit LoRA 更新梯度分支。 | < 0.1% | **显存开销非常低**。支持在单张中端卡或 80G 显存上微调大参数量模型。 | 量化和反量化转换会让训练吞吐率下降 30%~50%，训练时间拉长。 | 显存资源非常受限，且底座模型尺寸较大的场景。 |
| **DoRA** | 将权重分解为幅值（Magnitude）和方向（Direction），仅用 LoRA 模式优化方向。 | 0.1% ~ 1% | 逻辑拟合更平稳，最终多框架泛化性能指标常**优于普通 LoRA**，逼近全量微调。 | 训练期有额外的方向权重更新计算开销，速度慢 10%~20%。 | 追求微调质量上限，算力支持充分的 PEFT 场景。 |

### 3.4 评测检验

当前评测采用大模型综合评测，覆盖语法正确性、算法正确性、API 调用准确性、代码可编译性、单元测试通过率等多个维度。

*   **题目与类别完全隔离**：利用 [scripts/verify_holdout_dataset.py](scripts/verify_holdout_dataset.py) 强制检测。训练集和验证集不允许出现同类 Prompt Family（改参数生成的相似题目）或者 Example ID 的交叉渗漏，确保在未见过的题目上验证泛化性。
*   **Pass@1 代码真实执行评测**：编写自动化 CPU 评测沙盒，将模型生成的代码接入真实的 Python/Qiskit 运行环境，由程序自动在这些真实环境中执行。只有执行输出与基准误差符合精度拒绝限度（$\epsilon = 10^{-6}$），且完全符合单元测试的才判定为正确。

## 4. 实验参数设置

### 4.1 核心数学公式基础

*   **LoRA 权重投影数学模型**：
    使用低秩分解降低可训练参数规模，并采用高倍放大的 $\alpha$ 因子保障特定量子高阶先验不被稀释：
    $$W = W_0 + \Delta W = W_0 + \frac{\alpha}{r} (B \cdot A)$$
    其中 $W_0 \in \mathbb{R}^{d \times k}$ 为冻结的基座模型权重；秩 $r \in [16, 64]$；$\alpha \in [32, 128]$ 作为稳定比例缩放因子，$B \in \mathbb{R}^{d \times r}$，$A \in \mathbb{R}^{r \times k}$ 为可训练的低秩瓶颈权重。

### 4.2 推荐细化训练参数

*   **秩与缩放**：`--lora-rank 64`，`--lora-alpha 128`，`--lora-dropout 0.0`
*   **学习率与调度**：设置学习率最高为 `2e-4`，使用余弦退火（Cosine Decay）结合 `min_lr=2e-5`，最前期进行 3% 的 Warmup。
*   **微批次聚合（Batch Strategy）**：多卡分布式单卡 `per_device_batch_size=1`，配置 `gradient_accumulation_steps=8`，保证分布式等效最大 Total Batch Size 可以按多卡优雅累积，兼顾内存开销。
*   **上下文长度演化**：起始设为 `--max-length 2048`；在进行长上下文评估时由 2k 随后的多轮迭代分步扩增到 8k 和 16k。

### 4.3 分层微调对比实验（计划）

已有研究表明 Transformer 各层分工不同：浅层主要编码词法和表层特征（术语、API 搭配），深层负责语义组合与抽象推理（Tenney et al., arXiv:1905.05950；Geva et al., arXiv:2012.14913）。Surgical Fine-Tuning（arXiv:2210.11466）进一步指出：输入侧偏移（新框架、新术语）调浅层收益大，任务侧偏移调深层收益大。

据此我们计划做一组对照实验：只在浅 1/3 层挂 LoRA、只在深 1/3 层挂 LoRA、全层挂 LoRA（现状），三组保持可训练参数量基本一致，用 Track A 验证集的 Pass@1 对比。预期 API 调用准确性主要靠浅层，长链推理主要靠深层，结果将用于指导后续按层分配 LoRA 容量。

除了按层对比，我们还计划对**不同参数矩阵**做微调对比实验。LoRA 原始论文（Hu et al., arXiv:2106.09685）的消融实验表明：在总可训练参数量相同的前提下，只调注意力的 Q 和 V 矩阵效果最好，优于只调 Q 或只调 K；而后续实践（如 QLoRA, arXiv:2305.14314）发现把 LoRA 挂到全部线性层（Q/K/V/O + MLP 的 up/down/gate）通常能进一步提升效果。两类参数的作用也不同：注意力矩阵（Q/K/V/O）主要影响模型"关注什么信息"，MLP 层则主要存储事实知识（Geva et al., arXiv:2012.14913）。据此设计对比组：

*   只调 Q、V 矩阵（LoRA 论文推荐的最小配置）；
*   只调注意力的 Q/V/O 矩阵（K 矩阵微调收益小，不调）；
*   只调 MLP 层（up/down/gate），验证 API 知识是否主要存在 MLP 中；
*   全部线性层（现状基线）。

四组同样保持可训练参数量基本一致，用 Track A 验证集对比，找出"参数量最省、效果不降"的配置。

不同能力目标与建议微调层的对应关系如下：

| 能力目标 | 偏移类型 | 建议调的层 |
| :--- | :--- | :--- |
| 多框架 API 准确性（Qiskit/Cirq 接口混淆） | 输入侧偏移：表面形式变了，推理方式不变 | **浅层**（前 1/3 特征提取层） |
| 编程算法能力（算法、控制流、数据结构） | 主要是任务侧：语言和 API 都见过，缺组合与规划 | **中层 + 深层**（后 1/2~2/3），中层存知识与组合模式，深层负责生成决策 |
| 科学推理能力（多步推导、物理/数学约束） | 几乎纯任务侧：抽象推理链 | **深层为主**（后 1/3），可适当带上中层，浅层基本不动 |

### 4.4 RAG 与微调的组合方案

根据已有研究，"RAG + 基于代码样本的微调 + 基于文档的微调"组合效果优于单独使用任何一种：

*   **微调与检索互补**：微调负责固化输出格式和推理习惯，检索负责注入易变的事实知识（如频繁更迭的框架 API）。对比研究表明，对于知识注入，RAG 普遍优于纯微调，而两者结合在领域问答上得分最高（Ovadia et al., arXiv:2312.05934；Microsoft 农业领域实证，arXiv:2401.08406）。
*   **RAFT（检索感知微调）**：在微调数据中混入检索到的文档（含干扰文档），训练模型学会"引用相关、忽略无关"，使微调后的模型与 RAG 流水线协同，在领域基准上明显优于"纯 RAG"或"纯微调"（Zhang et al., arXiv:2403.10131）。
*   **文档检索增强代码生成**：DocPrompting 证明，生成代码时检索官方文档片段拼入上下文，能显著提升对训练后才出现的新 API 的调用正确率（Zhou et al., arXiv:2207.05987），这正对应量子框架接口频繁变更的痛点。

落地方式：在现有两条 SFT 线路之上，构建 Qiskit/Cirq/ISQ 官方文档向量库（复用 quantum_rag/ 模块），推理时检索拼接；后续按 RAFT 思路在训练样本中加入检索文档，让模型适应带检索的工作模式。

### 4.5 Q-Intelligence 智能体

将模型接入智能体框架，对模型的使用和提升都有直接好处：

*   **降低使用门槛**：用户用自然语言描述需求，智能体自动完成检索文档、写代码、运行、看报错、修复的完整流程，不需要用户自己拼接上下文。
*   **执行反馈闭环**：智能体能把编译错误和运行结果回传给模型再次修改，多轮迭代显著提高最终代码的通过率，弥补单次生成的不足。
*   **主动调用 RAG**：由模型自主决定何时检索、检索什么（Self-RAG, arXiv:2310.11511），比固定检索拼接的准确率更高，也能充分发挥已发布的无极量智 v0.1.0 检索库。
*   **产生训练数据**：智能体的真实使用轨迹（规划、调用工具、纠错、最终通过）经过拒绝采样过滤后，本身就是高质量的轨迹克隆训练数据，形成"使用越多、模型越强"的数据飞轮。
*   **暴露真实短板**：智能体日志能直接定位模型在哪类 API、哪类任务上最常出错，为后续微调的数据补充提供依据。
