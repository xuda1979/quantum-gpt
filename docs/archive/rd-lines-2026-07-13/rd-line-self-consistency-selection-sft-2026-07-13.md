# Track N9 — Self-Consistency Selection SFT (SCS-SFT)

**Owner:** subagent track (loop 2026-07-13, iteration 15:25)
**Status:** design + scaffold
**Target students:** Qwen3.6-27B (ASI1), Qwen3.6-35B-A3B (ASI2/3)
**Constraint:** post-training only; no architecture change.

## Problem

N2 trains a *critic* to judge pass/fail. But the critic is only useful if
the base model can **generate multiple candidates** and **select among
them**. Currently the pipeline emits one roll-out per task. A
self-consistency layer (generate K, score each, pick best) is standard in
code-generation but not wired into the inference path.

This track produces the SFT data for the *selection* step: given K candidate
programs and their execution results, the model learns to output the index
of the highest-scoring candidate. This is a small, learnable skill that
composes with N2's critic.

## Approach

Build an SFT set of (prompt, completion) pairs where:

- **prompt** = task spec + K candidate programs + their execution results
  (pass/fail + stdout).
- **completion** = the index of the best candidate (highest execution score,
  ties broken by shortest program).

The K candidates are drawn from the existing roll-out artifacts in
`data/generated/` (where available) and from synthetic mutations of the
reference candidate otherwise.

## Data source

- Tasks: the 58-task `evals/tasks/quantum/` directory.
- Candidates: reference `candidate.py` + 3-4 mutations (import error, prose,
  wrong output) generated by the N1/N3/N6 mutation helpers.
- Execution results: ground-truth from `tests.py` subprocess runs.

## Success metric

On a held-out 20% split, an SCS-SFT-LoRA adapter must pick the
execution-passing candidate **≥ 90% of the time** when at least one of K
passes (random = 1/K ≈ 25% for K=4).

## Out of scope

- Any NPU run.
- Wiring the selector into the live inference pipeline (follow-up once
  ≥90% is verified).
- Modifying the SFT trainer.
